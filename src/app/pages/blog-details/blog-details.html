HEAD and DETACHED HEAD are fundamental Git concepts that can transform how you manage your codebase. Understanding HEAD allows you to recover from mistakes quickly.

Before moving ahead, let’s look at a few commands that use HEAD. You must first understand what Git HEAD is. 


  git checkout HEAD~1
  git reset HEAD^1 --soft
  git reset HEAD^1 --hard
  git diff HEAD
  git reflog

What is Git HEAD?

Imagine each commit as a page in a book. HEAD acts as a bookmark showing your current page. You can flip to any page, but HEAD points where you are currently working.

Detached HEAD

When HEAD points to a commit other than the latest in a branch, it’s in a Detached HEAD state.

Analogy: Imagine flipping to an earlier page in a book. You can read or write from there without moving the main bookmark. 


  git checkout <commit-hash>
  git checkout -b new-branch

Best Practices

  • Check whether HEAD is attached or detached before committing.
  • Use git reflog to see HEAD history.
  • Create short-lived branches for experiments.
  • Double-check commands that move HEAD (git reset, git checkout).

Conclusion

In one sentence: HEAD is where you are in Git history.
